# BODY TONE FITNESS — REAL BACKEND

This package uses Supabase for real authentication, member profiles, bookings and private reports.

## Required one-time setup

1. Create a Supabase project.
2. Run `supabase_schema.sql` in Supabase SQL Editor.
3. Create a PRIVATE Storage bucket named `medical-reports`.
4. In Supabase Project Settings → API, copy:
   - Project URL
   - Publishable key (or legacy anon key)
5. Put those two values into `config.js`.
6. In Supabase Authentication → URL Configuration, set your Netlify URL as the Site URL.
7. Redeploy the whole folder to Netlify.
8. Open `https://YOUR-NETLIFY-SITE/connection-test.html`.
9. Create a member account.

Never put a `service_role`/secret key in `config.js`.

## Why the current site says "Failed to fetch"

The package that was deployed does not contain your actual Supabase project credentials. Those values are unique to your Supabase project, so they cannot be generated by the website itself. The fixed package now gives a specific setup message and includes `connection-test.html`.

SMS/WhatsApp reminders still need their provider/server-side integration before launch.

## Test booking rules
- Test dates are entered as `DD/MM`; the year is handled automatically.
- A test must be booked at least 4 hours before its selected time, both in the UI and (when the SQL file is run) at the database level.
- Members can cancel a confirmed Blood Test or BMI Test from My Profile only when 4 or more hours remain before the appointment.
- Run `test_booking_cancellation.sql` in Supabase to enforce the 4-hour cancellation rule server-side as well.


## Test cancellation
- Members cancel confirmed tests from Profile → Test Bookings.
- Cancellation is blocked when less than 4 hours remain.
- Cancelled bookings disappear from the member profile immediately after cancellation.
- Cancelling a BMI test also clears its pending retest reminder.
- Supabase must have the `cancelled_at` column from `test_booking_cancellation.sql`.

## Password reset
The site includes an OTP-based password reset page. It uses the shared Supabase configuration from `config.js`, so the "Supabase configuration is missing" error is fixed. Gmail SMTP must be configured in Supabase Auth → Emails as already set up.
